## 1. 요구사항과 결정 현황

### 1.1 확정된 동작
1. 최초 스킬트리 화면은 **정사각형 사령부 노드 하나만** 보여준다. 클릭하면 공통 정보창이 열리며 노드 클릭 자체로는 활성화되지 않는다.
2. 정보창은 모든 노드 공통으로 **짧은 설명 / 업그레이드 목록·레벨·비용·버튼(설정된 항목만 표시) / 주요 행동 버튼**을 사용한다. 잠금 노드도 클릭 가능하며 요구 웨이브 및 선행 노드를 보여준다.
3. 사령부 정보창 `배치`: 비용을 지불하고 건설군 공통 진행 연출 후 우측 전장 중앙에 사령부가 생긴다. 이때 **병영 신규(!), 공장 잠금(자물쇠), 비행장 잠금(자물쇠)**이 공개된다.
4. 병영 정보창 `건설`: 비용 지불·건물 진행 연출 후 보병 연구 노드 공개. 첫 연구는 소총 훈련만 바로 해금. 소총 훈련 정보창 `연구`: 비용 지불·연구 연출 후 소총병 자동 해금.
5. 소총병 노드 `배치`: 우측 **단일 전장**의 빈 개방 칸에 1명 비용을 내고 즉시 수준으로 자동 배치한다. 드래그 안내 후 유닛을 전장 안에서 이동·교환할 수 있다. 첫 웨이브에는 **소총병 2명** 배치 후 `전투 시작` 버튼으로 전투를 연다.
6. **미개방 배치 칸은 그리지 않고 입력도 받지 않는다.** 별도 HTML 5×5 배치 그리드는 제거하고, Phaser 전장에서 준비와 자동 전투를 모두 표현한다. 지형 자체는 유지 가능.
7. 우측 정찰 정보는 실제 공격 방향의 **북/남/동/서 공간 위치에 놓인 플로팅 박스**로 제공한다. 정찰은 방향만 정확히 알리고 병과·수량은 `?`. 준비 내내 유지. 첫 단계는 북·남.
8. 좌측은 웨이브 `현재/100`, 보유 군수물자, 기술트리, 노드 상세·투자 및 트리 이동/확대. 우측은 사령부 현재/최대 HP, 정찰, 배치 및 `전투 시작`, 재생/결과. **전체 공통 상단 HUD를 전제로 하지 않는다.** 설정·저장·도움말·타이틀·종료는 ESC 메뉴. 하단 상시 상태창 제거, 오류 등 일시 피드백은 비점유형 토스트/인라인 안내.
9. 공개된 노드는 **다른 노드를 선택하거나 선행 노드를 환불해도 화면에 남는다.** 공개 이력과 현재 잠금·완료 여부를 분리한다. 활성화가 끝난 노드의 직계 후속 노드만 새로 공개한다.
10. **자물쇠** = 보이지만 조건 미충족; **느낌표** = 조건을 처음 만족해 생긴 새 노드. 신규 해금 노드를 **클릭하면 느낌표 영구 제거**(환불·재해금·로드 후에도 다시 생기지 않음). 드래그만으로 클릭 처리 금지. 완료는 별도 표시.
11. 노드 **정사각형** 형태. 노드 또는 빈 배경을 드래그하면 **기술트리 전체를 팬(pan)**한다. 이동 거리 임계값으로 탭/클릭과 드래그를 분리하고, 포인터 캡처 해제·화면 경계 처리. 마우스 휠 확대와 중앙 복귀 지원.
12. 조건은 **선행 노드 완료 AND (필요할 경우) 최소 웨이브**. 기본 연구 중 일부는 선행 노드만 조건으로 한다. 웨이브 도달 자체는 연구/건설을 자동 완료시키지 않는다.
13. **건물·연구·유닛 활성화에는 군수물자 비용이 필요하다.** 진행 버튼은 왼쪽에서 오른쪽으로 채워지고, 좌측 군수물자 숫자는 이전 금액에서 이후 금액으로 감소·환불 때 증가하는 애니메이션을 사용한다.
14. 진행 시간은 **노드별 개별 수치가 아닌 종류별 공통 값**. 현재 연출 후보: 건물·사령부 3초 / 연구 2초 / 전투 유닛 배치 거의 즉시. 확정 시간은 아니며 데이터에서 조절한다. **환불에도 동일한 버튼 채우기 연출**을 사용한다. 환불 종류별 속도도 공통 정책으로 관리.
15. **시설 및 연구에 지출한 실제 금액은 준비 단계에서 100% 환불**한다. 선행 노드 환불 시 의존하는 하위 노드·강화·현재 웨이브 배치를 함께 원자적으로 취소하고 환불액/제거 목록을 먼저 확인한다. 현재 준비 단계의 유닛 배치 취소는 100%, 이미 전투에 사용된 유닛 생산비는 환불되지 않는다. 재구매/환불 반복은 돈을 증식하지 않는다.
16. **모든 종류의 노드는 향후 여러 업그레이드를 가질 수 있다**(사령부·병영·공장·비행장·연구·유닛). 지금 효과를 임의로 추가하지 않는다. 업그레이드 정의가 없으면 정보창에서 그 목록만 숨긴다. 기본 활성화와 업그레이드 단계는 각각 별도 저장한다.

### 1.2 구현 전에 결정·승인해야 할 좁은 범위
- **사령부 자체의 환불**: 일반 건물 100% 환불 원칙에서 사령부만 예외로 둘지 사용자가 최종 확정하지 않았다. **본 문서의 안전한 구현 기본안은 '사령부 최초 배치 이후 환불 불가'**이다. 사령부는 진행 루트이자 유일한 패배 목표이므로 일반 환불을 허용하려면 전장 철거와 모든 기술·배치 일괄 롤백, 사령부 미배치 상태 재진입을 별도 정의해야 한다. 후속 구현 착수 전 이 예외를 승인받거나 명시적으로 변경할 것.
- **모든 현재 투자 환불 후에도 유닛 구매가 불가능한 경우의 복구 정책**: 선행 웨이브에서 이미 소비한 유닛 비용은 환불할 수 없다. '최소 자금 강제 보유'는 채택하지 않음. **추가 구제 지급/이전 웨이브 롤백/자금 보장 규칙을 현재 확정하지 않음**. 아래 §6 게이트에서 실제 재시도 자금 고갈 사례가 발견되면 해당 결과를 제시하고 정책 결정을 요청한다.
- **시설 및 연구 업그레이드 효과·가격·환불 범위(특히 기본 건물 업그레이드)**: 스키마는 허용하되 실제 효과/수치는 추가 정의 전 사용 불가.
- ESC의 전투 중 저장/메뉴 진입 제약은 기존 저장 정책을 유지: 전투 중 저장 불가, 메뉴 진입 시 재생 일시정지; 메뉴 닫으면 사용자가 일시정지한 상태는 유지.

## 2. 상태 모델과 연결선 계약

### 2.1 노드 종류
`hq` / `building` / `research` / `unit`. 모든 노드는 고유 ID를 유지한다. 표시·상호작용 상태를 단일 `status` 문자열에 과도하게 합치지 말고 다음을 분리한다.

- `revealedNodeIds`: 일단 공개된 노드 영구 보존.
- `acknowledgedNodeIds`: **실제로 해금 가능 상태가 된 후** 정보창 클릭으로 신규 알림을 확인한 이력; 영구 보존. 잠금 중 정보창 열람은 느낌표 확인으로 처리하지 않음.
- `buildingIds` 또는 HQ 설치 상태 / `researchIds`: 실제 활성화 완료.
- `unlocked(node, wave, completed)`: 실제 조건 충족; 수동 활성화/공개 이력과 별개.
- `upgradeLevels[nodeId][profileId]`: 노드 종류와 무관하게 확장 가능.
- `investments`: 실제 지출액, 환불 금액, 하위 의존 환불과 일치하는 불변 거래 원장.
- `phase`, `animation`: **연출은 영속 게임 판정 상태에 영향을 주지 않는다.** 명령 한 번에 전체 비용과 상태가 원자적으로 확정되며 UI에서 변화 과정을 시각화한다. 중간 종료/재시작은 완료 상태로 복원하고 중복 차감하지 않는다.

### 2.2 연결 관계의 두 목적을 분리
- `revealEdges`: 다음 노드가 언제 화면에 보일지 결정. HQ 배치 완료로 병영·공장·비행장 공개. 병영 건설 완료로 연구 공개. 연구 완료로 유닛/연구 공개.
- `requirementEdges`: 실제 해금·환불 의존성. 예: 대전차 연구 → 공장; 장갑차 연구 → 비행장.
- `minWave`: 독립적인 AND 조건; 없으면 웨이브 제한 없음.
- `producerId`: 유닛 생산 시설의 활성화 필요. 환불 시 유닛 투자도 종속 처리.
- 실선/점선 또는 선택 노드 하이라이트로 '소속/공개'와 '필수 선행'을 시각적으로 구분한다. **단순히 가깝게 놓인 노드나 장식용 루트 선을 환불 의존 관계로 사용하지 않는다.**

환불할 연구의 후손에 건물이 있더라도 **건물도 환불 가능하므로 함께 취소할 수 있다.** 예: `atR` 환불 → `factory` → `carR`/기갑 분기 및 이들이 의존하는 후속 연구/시설/활성 배치 동시 환불. 실제로 관련 없는 형제 연구는 유지. 원천 연구의 투자금 100% 및 모든 연쇄 투자금 100% 반환.

### 2.3 가시성·알림 전이
- 새 게임: `revealed={hq}`, `completed={}`, `acknowledged={}`. 첫 화면 HQ 단독. HQ에 신규 느낌표 불필요.
- HQ `배치` 완료: HQ 완료 + 3개 시설 노출; 병영은 해금 가능이라 신규 `!`, 공장·비행장은 자물쇠.
- 병영 `건설` 완료: 연구 계열 공개; 소총 연구는 `!`, 나머지는 자물쇠.
- 소총 연구 `연구` 완료: 소총병 자동 해금; 소총병 노드 공개·신규 `!`.
- 잠금 상태 노드 클릭: 설명과 전체 조건의 충족/미충족 표시. 자물쇠나 공개 이력 변화 없음.
- 신규 느낌표 노드 클릭: 알림 확인 이력 기록, 다시 신규로 표시하지 않음.
- 완료 노드 클릭: 설명·완료된 투자·환불·기존 업그레이드 표시. **노드를 클릭해 다음 단계를 드러내는 것이 아니라 활성화 완료가 다음 단계를 드러냄.**
- 환불: 후속 노드는 화면에서 사라지지 않지만 현재 선행 조건에 따라 자물쇠로 변경. 확인한 느낌표는 되살아나지 않음.

## 3. 화면과 입력

### 3.1 좌측 기술트리
- 좌측 상단에 `웨이브 현재/100`, `군수물자 잔액`. 기술트리 확대·축소·원점 복귀 컨트롤은 좌측 안쪽.
- 노드는 폭=높이인 한 종류의 정사각형 베이스 + 별도 아이콘·자물쇠·느낌표·완료 배지(프로젝트 에셋 규약 우선). 이름은 읽을 수 있도록 노드 내부 또는 하단 레이블 규격으로 배치.
- 노드·빈 공간 모두 드래그 팬, 임계 거리 이상의 이동은 클릭/알림 확인으로 취급하지 않음. 노드 위치/연결선·뷰포트 중심·줌 유지. 트리 맨 처음에는 사령부로 중앙 정렬.
- 노드 상세는 **항상 동일한 공통 정보창**: 노드 이름/짧은 정의/잠금 조건 및 현재 상태/설정된 업그레이드 목록·레벨·효과·비용·버튼/행동(배치·건설·연구)/환불(가능한 노드)/닫기. 특정 건물의 하위 시설 목록은 그래프 자체로 확인하므로 상세에 별도 반복 나열할 필요 없음.
- 전투 중에는 정보 열람은 가능하지만 연구·건설·강화·환불·배치 명령은 잠금.
- 기존 좌측 하단 `.tech-details` 패널과 게임 전체 하단 `.message` 상시 상태창 제거.

### 3.2 우측 단일 전장

### 3.3 버튼 진행 효과 및 경제 표시
- 일회성 건물/HQ 3초, 일회성 연구 2초, 반복 전투 유닛 배치는 거의 즉시: **노드별 추가 시간 차등 없음**. 모두 조정 가능한 유형별 UI 설정이며 임시 수치.
- 버튼 자체가 좌→우로 채워지는 진행 그래프. 환불도 **같은 공통 컴포넌트** 사용(건물/연구 등의 유형별 시간 연동 기본안, 세부 시간은 튜닝 가능). 환불 실행 전 영향을 받는 투자와 실제 환불 총액 확인.
- 군수물자 UI는 거래 전→후 금액 사이를 숫자 애니메이션으로 표현. **게임 상태 자원은 프레임별 차감이 아니라 명령 하나의 원자적 전액 거래**. 애니메이션 중 재클릭·전투 시작·중복 명령 방지.

- `prefers-reduced-motion` 또는 게임 내 움직임 줄이기 설정이면 애니메이션을 생략/축소하되 결과·자원 값은 동일하게 처리.

`docs/IMPLEMENTATION_STATUS_2026-10-26.md` 및 보존된 보고서에 기록된 기존 시뮬레이션은 **총 13,000건의 독립 정책·시드 캠페인**이다(본 시드 9,000 + 홀드아웃 4,000). 그중 `respec`은 본 시드 1,000 중 779, 홀드아웃 1,000 중 774가 100웨이브를 완주했으며, 양쪽에서 회계 오류 0건. 본 시드 `recon` 880/1,000, `mixed` 851/1,000; 별도 시드 `recon` 868/1,000, `mixed` 855/1,000. 구체 보고서는 `docs/balance-reports/candidate-v11-refund-final-1000-analysis.md` 및 `candidate-v11-refund-holdout-final-1000-analysis.md`.

**한계:** 이들은 **기존 사령부·병영·소총 연구 시작 완료, 웨이브 게이트 없는** 현행 소스를 검증한 결과다. 지금 문서의 유료 시작·시설/연구 해금 조건·새 환불 UI를 검증한 결과로 인용해서는 안 된다. 기존 시스템은 기본 노드 환불을 막아두었으므로 새 HQ/병영 환불의 합격 근거도 아니다.

### 5.4 신규 후보 경제 시나리오 반복 검증(실제 실행, 전투 판정 아님)
이 문서를 만들면서 **현행 비용·웨이브 보상·진형 칸 수·§4 선행/웨이브 조건을 입력한 독립 JavaScript 경제 모형**으로 1,000시드 × 3정책 × 3초기 자금(140/160/180) = **9,000회 100웨이브 경제 경로**를 계산했다. 정책 `low/mixed/refund`는 유닛 구매 구성과 투자를 서로 다르게 진행하고, `refund`는 5웨이브마다 투자 환불·재구매를 시도한다. 해당 모형은 **모든 웨이브를 승리했다고 가정**하여 주어진 승리 보상만 누적하며 적/승패를 계산하지 않는다.

| 시작 자금 | 1웨이브 소총 2개 편성 성공(각 정책 1,000건) | 100웨이브 중 회계 불일치/음수 잔액/선행 모순 |
| --- | --- | --- |
| 140 | 1,000/1,000 × 3정책 | 각 0 |
| **160** | **1,000/1,000 × 3정책** | **각 0** |
| 180 | 1,000/1,000 × 3정책 | 각 0 |

이 경제 모델에서 `refund` 시나리오 1,000건은 총 **58,000회 환불 거래**, 환불 금액 합계 **24,487,060**, 회계 오류 0이었다. 단 **새로운 엔진의 공식 `RefundService`를 실제 호출한 검증이 아니라 모형 자체의 회계·조건 검사**이며, 100% 승리 가정 때문에 후반 잔액이 낙관적으로 누적된다. 이 결과로 웨이브 보상 충분성이나 재도전 소프트락 부재를 확정할 수 없다.

## 6. 후속 구현의 필수 시뮬레이션/합격 게이트

### 6.1 구현 전후 두 버전 비교
- 기존 `candidate-v11` 데이터/소스/13,000건 결과 **보존**. 새 후보는 `candidate-v12-tech-tree` 등 신규 데이터 파일로 작성하고 `active.json`을 조기에 변경하지 않음.
- 첫 구현 후보: `initialSupplies=160`, `costs.hq=30`, `costs.barracks=30`, 나머지 비용·유닛 수치는 기존 v11 기준선, 보상은 위 5개 구간. §4의 `minWave` 적용 후 **새 정책 코드와 함께** 검증.

- 권장 본 시드 **정책별 N=1,000**(`recon,mixed,wrong,respec` 이상), 독립 홀드아웃 **정책별 N=1,000**, 정찰 방향만 이용. 합계 최소 **8,000번의 100웨이브 캠페인 시도**. 환불/구매 왕복·배치 취소·선행 연구 환불·건물 동반 환불을 별도 1,000시드 × 20거래 = 20,000거래 이상 검증. 자금 고갈/재시도 가능성을 실패한 캠페인마다 검사.

## 8. 이 기준서로 후속 구현을 요청하는 방법 / Git 통합

**main은 변경하지 않는다.** 설계 문서가 존재하는 상태로 main을 체크아웃하거나 문서를 main에 먼저 병합하지 않는다. 아래처럼 **저장소 밖 임시 보관 → main에서 작업 브랜치 생성 → 그 브랜치에 문서 이동** 순서로 진행한다.

현 세션에서 사용하는 임시 보관 경로:
`C:\GPT-Workspace\ww-tech-tree-handoff-20261027\TECH_TREE_BATTLE_UI_IMPLEMENTATION_SPEC_2026-10-27.md`

실행 순서:
1. `git status --short`로 작업 트리 확인. 설계 문서를 저장소 **밖**으로 잠시 옮기고 작업 트리가 깨끗한지 확인한다.
2. `git switch main`으로 기준 브랜치를 선택하되 **main을 수정하거나 commit하지 않는다**. 이어 `git switch -c feat/tech-tree-battle-ui-implementation`로 main의 HEAD에서 구현 브랜치를 만든다. 협업 변경이 있는 경우 먼저 확인하고 덮어쓰지 않는다.
3. 임시 보관한 설계 문서를 `C:\GPT-Workspace\ww\docs\TECH_TREE_BATTLE_UI_IMPLEMENTATION_SPEC_2026-10-27.md`로 되가져온다. 그 후 **구현 브랜치에서만** 문서를 커밋한다. 이 문서는 구현과 검증의 단일 기준이다.
4. `docs/TECH_TREE_BATTLE_UI_IMPLEMENTATION_SPEC_2026-10-27.md`를 읽고 계약→로직→화면→저장→새 N회 전투·환불 검증 순으로 구현한다. 미승인 정책은 임의 확정하지 않는다. **main에서 직접 코드를 작성하지 않는다.**
5. 변경 내용과 검증 증거를 구현 브랜치에 커밋하고, 사용자 리뷰·승인 후에만 main으로 merge 또는 PR 병합한다.

PowerShell 참고(임시 보관 후 실행):
```powershell
cd C:\GPT-Workspace\ww
git status --short
git switch main
git switch -c feat/tech-tree-battle-ui-implementation
Move-Item "C:\GPT-Workspace\ww-tech-tree-handoff-20261027\TECH_TREE_BATTLE_UI_IMPLEMENTATION_SPEC_2026-10-27.md" ".\docs\"
git add docs/TECH_TREE_BATTLE_UI_IMPLEMENTATION_SPEC_2026-10-27.md
git commit -m "docs: add tech tree battle UI implementation spec"
git status
```
현재 세션에서 이미 문서 이동 및 브랜치 생성이 끝났다면 위 이동·생성 명령을 **다시 수행하지 말고**, 현재 브랜치가 목표 브랜치인지 확인한 후 문서 커밋만 실행한다. **커밋하지 않은 문서는 브랜치에 저장된 것이 아니라 작업 트리 파일**이다.

이 문서 자체는 **수치 실험과 설계 계약**이다. 기존 13,000 전투 캠페인과 이번 9,000 경제 경로/25,000 환불 모형 거래의 적용 범위를 명확히 구분하고, **새 실제 전투/새 환불 구현의 합격 여부는 아직 미측정**으로 둔다.
