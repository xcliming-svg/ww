# 구현 정적 검토 기록

이 기록은 원본 문서를 수정하지 않는 추가 문서다. 허용된 정적 검사 및 순수 Node 밸런스 측정과 소스 검토를 구분한다. 브라우저, 실제 입력, 스크린샷, 플레이 QA, 성능, Electron 기동/설치, 실행형 단위 테스트는 시행하지 않았다.

별도 리뷰 에이전트는 사용량 제한으로 실행되지 못했다. 독립 리뷰 합격을 주장하지 않는다. 아래는 구현자가 변경 후 별도로 소스를 재검토한 결과다.

| 경계 | 구현 및 정적 검토 근거 | 검증 한계 |
| --- | --- | --- |
| 준비 거래 | `EconomyService`: validateState → phase/commandId → 복제 상태 거래 → validateState → Result. 잔액/비용은 안전한 정수. 취소는 paidCost 반환 | 실제 버튼 연타/입력 QA 없음 |
| 영구 투자 환불 | `InvestmentLedger`, `RefundService`: 보유 연구·강화와 지출 원장 일치, 실제 parentIds/producerId 의존 폐쇄, protected 기본 노드, 미리보기 토큰, 하나의 상태 교체 | 환불 후 재구매 정책은 밸런스 CLI에서 측정. 저장/UI 복원 실기는 없음 |
| 배치 | `FormationService`: 범위/열린 칸/중앙 HQ 제외. 이동과 교환이 paidCost를 바꾸지 않음. 환불 시 영향을 받는 유닛만 취소 | 드래그의 실제 브라우저 동작 미검증 |
| 전투 | `StepSimulation`: 고정 tick, 예약 스폰까지 소진 후 승리, 범위 내 최근접, 방사형 아군 공격, 적 지속 전진/공격, 동시 피해 묶음에서 HQ 사망 우선 | Node 밸런스는 렌더/체감 증거가 아님 |
| 종료/재시도 | `Campaign`: 전투 전 checkpoint 복제, 보상 resolutionId 중복 차단, 100 이후 진행 거부, 실패 시 checkpoint 복원. 원장도 함께 복원 | 상태 전이 실행형 단위 테스트 없음 |
| 계산/재생 분리 | Worker가 같은 도메인을 계산. `GameCoordinator.update`는 30초 재생 위치만 변경. 배속/일시정지는 결과/seed를 바꾸지 않음 | 프레임 지연에서 시각 FX 누락/표시 품질은 미검증 |
| 비동기 명령 | 전투 시작 저장 이전 calculating 잠금, 계산/로드/종료 저장 중 변경 거부, Worker 실패 시 checkpoint 복구, 저장된 snapshot과 현재 state 동일성 비교 | 실제 브라우저 Worker 실패 주입 없음 |
| 저장 | v2 스키마, SHA256, 직렬 쓰기 큐, 임시 파일+fsync+rename, 이전 정상 백업/손상 원본 보존. 전투 중 저장 금지 | 디스크 고갈/권한 오류/프로세스 강제 종료 실험 없음 |
| v1 호환 | 원래 스키마·체크섬 먼저 검증. 동일 config 또는 명시 가격 호환표만 허용. candidate-v10/v11 → candidate-v11-refund1은 실제 비용표/강화 비용을 대조한 뒤 원장 복원 | 알 수 없는 이전 후보는 SAVE_MISMATCH. 임의 가격 추정 없음 |
| 트리/입력 | 28노드 DAG, 직접 자식 중심 노출, ✓/! 및 접근성 상태, 다음 목표, 종류별 수치/필터, modal 확인/취소, Esc/F1 키 경로 | 화면 가림/포커스 이동 실제 QA 없음 |
| 수명 관리 | AbortController, app 구독 해제, Phaser shutdown, HMR beforeunload/close 해제. 새 게임/로드/다음 웨이브에서 frame·재생 시간 초기화 | 수십 번 씬 전환/메모리 측정 없음 |
| 문자열 | locale 키/플레이스홀더/미사용 키, 연속 ?와 U+FFFD 인코딩 손상 검사. 한국어 네이티브 파이프 인코딩으로 손상된 문구 복구 | 번역 추가 시 새 언어의 화면 폭은 재검증 필요 |
| 파일/배포 | 외부 런타임 요청 없음, 로컬 ww://game 프로토콜, IPC 발신 프레임 검증, 네트워크/새 창 차단, Noto OFL + npm 런타임 7종 고지 | 패키지 생성/기동/설치 성공을 뜻하지 않음 |

## 판정과 통계의 구분

- 후보 v10의 본 시드 8,000캠페인/보류 시드 3,000캠페인은 완료되어 별도 리포트와 소스 스냅샷을 보존했다. 환불 전 버전이다.
- 후보 v11은 공격기 사거리 4 → 4.8을 조정해 통제된 대장갑 교전에서 공격이 발동하도록 했다. 100% 환불 이후 최종 판단은 `candidate-v11-refund-*` 리포트를 사용한다.
- 피해 기여량은 동시 공격의 초과 피해가 일부 중복될 수 있는 추정 지표다. 정확한 승패와 HQ 잔여 HP를 주된 비교 지표로 사용한다.
- 동일 4칸 병과 역할 프로브는 병과마다 구매비가 다르다. 상위 유닛의 승리율을 동일 비용 효율 우위라고 해석하지 않는다.
- 최종 적합성·진행률·미완료 항목은 이후 별도 상태 문서의 I-01~23 근거를 따른다.

## 저장 경로 보충

실제 저장 payload는 schemaVersion=2다. 기존 파일을 찾을 수 있도록 저장 위치 이름은 `app.getPath('userData')/campaign-v1.json`, 브라우저 대체 키는 `ww.campaign.v1`을 유지한다. `v1` 이름은 위치 식별자이며 payload 버전 판정에는 쓰지 않는다. 설정 키는 별도 `ww.settings.v1`이다.

## 후속 세션 시작 보고

작업을 시작할 때 진행률을 먼저 알린다. 마지막 상태 문서의 체크리스트와 현재 Git/코드를 확인한 뒤, 에셋 연결을 제외한 기능 구현과 최종 출시 준비를 구분해 보고한다. 다른 세션의 에셋 문서/산출물은 사용자가 연결을 요청하기 전까지 다루지 않는다.
